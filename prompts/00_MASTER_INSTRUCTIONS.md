# Permanent implementation instructions

Act as the backend implementer for this securities-lending training project. Read this file, db/README.md, db/TABLE_OWNERSHIP.md, docs/DECISIONS.md and existing code before each task. Implement the requested stage with real code, tests and runnable commands. Do not claim an unrun test passed. Do not replace completed stages with stubs or rewrite unrelated files.

Fixed design:
- Java 21, Spring Boot 3.x, Maven; four independently runnable services: Security & Market Data, Custodian, Borrower, Valuation & Accrual. QuickFIX/J is embedded only in Borrower/Custodian. No fifth business service, gateway, service registry or gRPC required.
- One MySQL server, four databases. Start with the supplied 48 physical tables. Do not add tables, including framework history/session/FIX tables, without showing why and staying within 50 total. No cross-database queries/FKs, shared entity modules or remote JPA associations. SQL bootstrap is explicit; Hibernate ddl-auto=validate, SQL auto-init disabled. No H2 substitution for MySQL integration tests.
- Master-data/MSLA/contracts/obligation reads use authenticated REST; Kafka carries workflows, FIX payloads, calculation jobs/results and market-price notifications. Bound REST timeouts. No database locks held across network calls.
- Each service owns its writes. Borrower owns intent; Custodian owns approval and authoritative obligations. Calculation provides results, never issues recalls, creates margin calls or executes payments itself. Local quantity arithmetic, permission/eligibility checks and state transitions remain Borrower/Custodian.
- MSLA default_rules stays backend-built/validated JSON. eligible_securities stays JSON of allowed asset types. Selected security uses ISIN; master uses its own local ID. collateral_type retains all supported ENUM values but current backend accepts only CASH; enforce effective haircut 0%, with coverage separate. Contract collateral_terms is an immutable approval snapshot; document any later amendment instead of overwriting history.
- Calculation input/price/rule snapshots are stored on calculation_run. Individual typed results and extra JSON details are stored on calculation_result. Use BigDecimal, explicit currency, documented scales, rounding, rate units and day-count. No double/float money. Same-currency CASH only until FX support is explicitly designed. Never invent a price on outage.
- Business calendar, timezone, cutoff and holiday coverage are versioned service configuration. T+1 means configured next business day. Recall deadline policy is separate. Inject Clock; never mark settlement complete merely because its date arrives.
- Original FIX codes remain AF, BB, BA, AE, AK, f, with corrected scenarios. AF queries real existing orders and receives 8 reports. It is conditional and does not initiate a locate. f is instrument status, not loan status. BB/BA carries the agreed collateral lab profile. AE reports agreed terms and triggers local acceptance; AK is TradeCaptureReportAck used as the business acknowledgement, never proof of settlement. Validate dictionaries/profile tags; do not silently repurpose standard fields. Add explicit agreed extension fields or JSON companion data where necessary.
- Kafka transport is not a TCP FIX session. Do not pretend Session.sendToTarget publishes Kafka or invent session sequencing semantics. Define the offline FIX header/profile and audit expectations explicitly.
- Authenticated issuer/subject/org comes from validated tokens, never frontend org fields alone. Shared OIDC identity infrastructure is external to the four business services. Separate service OAuth clients. Authenticate producer/consumer operations through Kafka ACLs plus application authorization.
- Outbox saved atomically with business state, publish acknowledged by broker, retries with leases. Consumer business writes + inbox dedup + response outbox commit together; only then acknowledge Kafka. Unique event IDs and persistent owner-row versions. A repeated message must not double reserve, accrue, settle, return, release or pay. Apply related events sharing a version carefully; event ID is dedup key.
- For a schema mismatch: show the exact issue first, propose the smallest column/index change in a separate reviewed SQL patch, preserve semantics and <=50-table cap. Do not rename fields/types silently. Explain existing-data migration separately; provided schema is fresh-create.

For each stage deliver: changed files, implementation explanation, exact commands, meaningful tests with actual results or explicit environment blockers, API/event examples and remaining dependencies. Maintain docs/PROGRESS.md with COMPLETE / PARTIAL / BLOCKED based on evidence. Do not call the application production-ready from a scaffold or unit tests alone.
